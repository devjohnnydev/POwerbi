01Desktop x Service

Você cria no Desktop; as pessoas consomem no Service (navegador, celular, Teams).

Power BI DesktopPower BI Service
Onde rodaWindows, instaladoNavegador: app.powerbi.com
Para quêImportar, transformar, modelar, criar relatóriosCompartilhar, atualizar automaticamente, painéis, aplicativos, alertas
CustoGratuitoGratuito para uso pessoal; compartilhar normalmente exige licença (Pro, Premium por Usuário ou capacidade da organização)

O vocabulário do Service

  • Workspace: pasta compartilhada de um time (ex.: “Comercial”). “Meu workspace” é sua área pessoal.
  • Modelo semântico (antes “conjunto de dados”): as tabelas, relações e medidas que você publicou.
  • Relatório: as páginas que você criou no Desktop.
  • Painel (dashboard no Service): uma página única com blocos “fixados” de vários relatórios.
  • Aplicativo: pacote de relatórios e painéis de um workspace, distribuído para um público.

02Publicando o relatório

  • Revise o checklist de design (aula 8) e de usabilidade (aula 12).
  • Oculte colunas técnicas (chaves, colunas “Num”) e tabelas auxiliares.
  • Dê descrições às medidas (painel Propriedades) para quem for criar visuais a partir do seu modelo.
  • Salve o .pbix.
  1. Entre com a conta corporativa ou de escola (canto superior direito do Desktop).
  2. Página Inicial → Publicar.
  3. Escolha o destino: Meu workspace (para treinar) ou o workspace do time.
  4. Quando aparecer “Êxito!”, clique em Abrir 'Dashboard_Vendas_Final.pbix' no Power BI.

No workspace aparecem dois itens com o mesmo nome: o relatório e o modelo semântico.

Teste filtros, drill-through, indicadores e botões. No Service, os botões funcionam com um clique simples (sem Ctrl). Confira as páginas ocultas: não aparecem na lista, mas o drill-through continua funcionando.

Passe o mouse sobre um visual → ícone de alfinete (Fixar visual) → Novo painel → Painel Executivo. Fixe os cartões e o gráfico principal. No painel, cada bloco leva de volta ao relatório de origem e permite configurar alertas (ex.: avisar quando o faturamento do dia passar de R$ 100 mil).

03Atualização automática

O relatório só é útil se mostrar dados de hoje.

FontePrecisa de gateway?Observação

Excel no OneDrive ou SharePointNãoCaminho mais simples para quem está começando
APIs públicas (IBGE, aula 7)NãoConfigure a credencial como Anônima
Banco de dados na rede da empresaSimGateway instalado num servidor da empresa
?
O que é o gateway

É um programa (gateway de dados local) instalado num computador que fica ligado e tem acesso aos arquivos. Ele faz a ponte entre o Service, na nuvem, e os dados dentro da sua rede. Existe o modo pessoal (só para você) e o padrão (para a empresa).

  1. No workspace, passe o mouse no modelo semântico → ⋯ → Configurações.
  2. Credenciais da fonte de dados: edite e entre (para APIs públicas, Anônimo).
  3. Atualização agendada: ative, escolha frequência (diária), fuso Brasília e horários (ex.: 07:00 e 13:00).
  4. Marque o envio de e-mail em caso de falha.
i

A quantidade de atualizações por dia depende da licença (com Pro costuma ser até 8 por dia). Agende para antes do expediente: o gestor abre o relatório já atualizado.

04Segurança em nível de linha (RLS)

Um único relatório, e cada pessoa vê só os dados dela.

Cenário: cada gerente regional só pode ver as vendas da sua categoria de produto. Modelagem → Gerenciar funções → Novo:

FunçãoTabelaFiltro DAX
Gerente EletrônicosdProdutos[Categoria] IN {"Notebook", "Celular", "Monitor", "Teclado", "Mouse"}
Gerente VestuáriodProdutos[Categoria] IN {"Casaco", "Camisa"}

O filtro na dimensão desce pelo relacionamento e filtra a fVendas automaticamente.

Modelagem → Exibir como → marque Gerente Vestuário → OK. O faturamento total deve cair para cerca de R$ 435 mil (Casaco R$ 288.666 + Camisa R$ 146.932,50). Clique em Parar de exibir.

Em vez de uma função por gerente, crie uma tabela dAcesso (E-mail, Categoria), relacione com dCategoria e use uma única função:

DAX · filtro na tabela dAcesso
[E-mail] = USERPRINCIPALNAME ()

Cada pessoa que abrir o relatório vê só as categorias ligadas ao e-mail dela. Para incluir um gerente, basta acrescentar uma linha na planilha de acessos.

No Service: modelo semântico → ⋯ → Segurança → escolha a função e adicione os e-mails. Atenção: quem é Administrador, Membro ou Colaborador do workspace enxerga tudo; a RLS vale para quem tem acesso de Visualizador ou recebe o relatório por compartilhamento ou aplicativo.

Publicar na Web é público

O link pode ser encontrado por buscadores e repassado para qualquer um. Muitas organizações desativam essa opção. Para o portfólio, use dados públicos (aula 7) ou fictícios.

06Layout para celular

No Desktop: Exibição → Layout móvel. Arraste os visuais do painel lateral para a tela do celular: cartões no topo, um gráfico por vez, segmentação de ano em blocos. Volte ao layout da Web pelo mesmo botão.

?
Por quê

Muitos gestores abrem o relatório no celular, entre uma reunião e outra. Sem o layout móvel, eles veem a página de 1920 px espremida.

07Projeto final do curso

Hora de mostrar tudo o que você aprendeu, com um tema escolhido por você.

Escolha uma base (uma das opções)

  1. Vendas: a base do curso, ampliada com devoluções, lojas e localidades;
  2. Dados públicos: IBGE, DATASUS, INEP (Censo Escolar), Portal da Transparência, dados.gov.br;
  3. Dados reais do seu trabalho, anonimizados (sem nomes, CPFs ou dados sensíveis).

08Atividades desta aula

A1 · Publique

Básico

Publique o Dashboard de Vendas no seu workspace e fixe 3 visuais num painel.

A2 · Teste de RLS

Intermediário

Crie as duas funções de gerente, teste com Exibir como e anote o faturamento que cada uma enxerga.

A3 · Versão celular

Intermediário

Monte o layout móvel da Visão Geral e tire um print do celular (aplicativo Power BI Mobile) ou do modo de exibição móvel do Service.

A4 · Exportação

Básico

Exporte o relatório para PDF (Arquivo → Exportar → Exportar para PDF) e compare com a versão interativa: o que se perde?

A5 · Projeto final

Entrega

Desenvolva e apresente o projeto final seguindo os requisitos e os critérios acima.
