01Conhecendo a fonte: IBGE e SIDRA

Antes de abrir o Power BI, você precisa entender de onde o dado vem. Analista que não conhece a fonte não sabe explicar o número que mostra.

?
Por que o IBGE

O IBGE é a fonte oficial de estatísticas do Brasil. Os dados são públicos, gratuitos, atualizados todo ano e têm uma API: o Power BI consegue buscá-los sozinho, e o seu relatório se atualiza com um clique quando sair a estimativa nova.

Acesse sidra.ibge.gov.br/tabela/6579. O SIDRA é o “banco de tabelas” do IBGE. A tabela 6579 traz a População residente estimada por município, estado e Brasil.

Se aparecer um balão “Dúvidas”, clique em Fim para fechá-lo.

Repare em três partes da tela, que existem em toda tabela do SIDRA: Variável (o que é medido), Ano (quando) e Unidade Territorial (onde).

Role até o bloco Ano. Por padrão só o último ano vem marcado. Marque também 2025, 2024, 2021 e 2020.

!
Observe

Não existem estimativas para 2022 e 2023. Nesses anos o IBGE fez o Censo e parou as estimativas. Guarde essa informação: ela vai aparecer de novo quando cruzarmos população com PIB.

  1. Em Unidade Territorial, desmarque Brasil.
  2. Marque Unidade da Federação [27/27]. As 27 UFs (26 estados + DF) entram de uma vez.
?
Por que não trazer o Brasil junto

O total Brasil é a soma dos estados. Se você importar os dois níveis, o Power BI vai somar tudo e o resultado sai dobrado. Traga só o nível mais detalhado e deixe o Power BI calcular os totais.

Na barra azul, clique em Visualizar. O SIDRA monta a tabela com estados nas linhas e anos nas colunas.

Conferir na fonte é um hábito profissional: quando o seu painel mostrar Roraima com 761.012 habitantes em 2026, você vai saber que o número bate com o IBGE.

É assim que a tabela aparece. Note que os números estão em pessoas e com separador de milhar brasileiro (ponto).

Feche o resultado e clique no ícone de corrente (Links de Compartilhar). O campo Parâmetros para a API é o endereço que o Power BI vai usar.

Vamos entender a URL, pedaço por pedaço:

/t/6579tabela 6579
/n3/allnível 3 (UF), todas
/v/9324variável 9324, população estimada (o site mostra v/all; deixamos explícito)
/p/last%205os 5 últimos períodos (%20 é o espaço)
?
Por que “last 5” e não os anos fixos

Com Usar períodos relativos marcado, quando o IBGE publicar 2027 o seu relatório passa a trazer 2027 sozinho ao clicar em Atualizar. Ano fixo na URL faz o relatório envelhecer.

Abra sidra.ibge.gov.br/tabela/5938 (PIB dos Municípios). Faça o mesmo: últimos 5 anos e Unidade da Federação. A variável que queremos já vem marcada: Produto Interno Bruto a preços correntes, código 37.

!
Leia a unidade

O PIB vem em Mil Reais. O valor 3.444.814.033 de São Paulo em 2023 significa R$ 3,44 trilhões, e não R$ 3,4 bilhões. Erro de unidade é o erro mais comum (e mais constrangedor) em BI. Vamos multiplicar por 1.000 no Power Query.

URL do PIB: https://apisidra.ibge.gov.br/values/t/5938/n3/all/v/37/p/last%205 (anos 2019 a 2023).

Falta uma tabela que diga qual região cada estado pertence e qual é a sigla. Abra no navegador:

https://servicodados.ibge.gov.br/api/v1/localidades/estados

O resultado é um JSON: uma lista de estados, e dentro de cada estado um objeto regiao. Esse “objeto dentro do objeto” é o que o Power Query chama de Record, e vamos expandi-lo.

O campo id (11 = Rondônia, 35 = São Paulo) é o mesmo código que o SIDRA usa. É ele que vai ligar as tabelas.

02Importando no Power BI com Power Query

Agora você vai trazer as três fontes para dentro do Power BI pela opção Web. Nada de baixar planilha: o Power BI conversa direto com a API.

Abra o Power BI Desktop e clique em Relatório em branco.

Na guia Página Inicial, clique na setinha de Obter dados e escolha Web.

?
Por que Web

O conector Web lê qualquer endereço que devolve dados: página HTML com tabela, CSV publicado ou API JSON, como as do IBGE.

Mantenha Básico, cole a URL da API de Localidades e clique em OK. Se perguntar sobre autenticação, escolha Anônimo e Conectar: a API é pública.

URL · dEstado
https://servicodados.ibge.gov.br/api/v1/localidades/estados

O Editor do Power Query abriu com 27 linhas e 6 colunas. Olhe o painel Etapas Aplicadas à direita: o Power Query gravou cada transformação, como uma receita (Fonte → Convertido para Tabela → Column1 Expandido → regiao Expandido → Tipo Alterado). Ao atualizar, ele repete a receita inteira.

Renomeie a consulta para dEstado no campo Nome (Propriedades, à direita).

Clique em Editor Avançado (guia Página Inicial). Substitua todo o código por este. Ele faz o mesmo que os cliques, mas com nomes de coluna claros:

Power Query M · dEstado
let
    Fonte     = Json.Document(Web.Contents("https://servicodados.ibge.gov.br/api/v1/localidades/estados")),
    Tabela    = Table.FromRecords(Fonte),
    Regiao    = Table.ExpandRecordColumn(Tabela, "regiao",
                    {"id", "sigla", "nome"},
                    {"id_regiao", "sigla_regiao", "regiao"}),
    Renomeado = Table.RenameColumns(Regiao,
                    {{"id", "id_uf"}, {"sigla", "sigla_uf"}, {"nome", "uf"}}),
    Tipos     = Table.TransformColumnTypes(Renomeado, {
                    {"id_uf", Int64.Type}, {"sigla_uf", type text}, {"uf", type text},
                    {"id_regiao", Int64.Type}, {"sigla_regiao", type text}, {"regiao", type text}})
in
    Tipos
?
Por que dEstado com “d”

Usamos um prefixo para o tipo de tabela. d = Dimensão: descreve coisas (quem, onde, quando), tem poucas linhas e uma linha por item. f = Fato: guarda eventos e números (quanto), tem muitas linhas. Essa separação é o modelo estrela, a base de todo modelo bom no Power BI.

No Power Query: Nova Fonte → Consulta Nula. Renomeie para fPopulacao, abra o Editor Avançado e cole:

Power Query M · fPopulacao
let
    Url       = "https://apisidra.ibge.gov.br/values/t/6579/n3/all/v/9324/p/last%205",
    Fonte     = Json.Document(Web.Contents(Url, [Headers = [Accept = "application/json"]])),
    // a 1ª linha do SIDRA é o "dicionário" das colunas (D1C = código da UF...). Pulamos.
    SemCabec  = List.Skip(Fonte, 1),
    Tabela    = Table.FromRecords(SemCabec),
    Colunas   = Table.SelectColumns(Tabela, {"D1C", "D3N", "V"}),
    Renomeado = Table.RenameColumns(Colunas,
                    {{"D1C", "id_uf"}, {"D3N", "ano"}, {"V", "populacao"}}),
    Tipos     = Table.TransformColumnTypes(Renomeado,
                    {{"id_uf", Int64.Type}, {"ano", Int64.Type}, {"populacao", Int64.Type}}, "en-US")
in
    Tipos

Resultado esperado: 135 linhas (27 UFs × 5 anos) e 3 colunas.

?
Por que jogar fora tantas colunas

A API devolve 11 colunas, mas o nome do estado, o nome da variável e a unidade de medida se repetem em todas as linhas. O nome do estado já está em dEstado. Fato bom é “magro”: só chaves (id_uf, ano) e números. Isso deixa o modelo leve e rápido.

Repita com outra Consulta Nula, nome fPIB:

Power Query M · fPIB
let
    Url       = "https://apisidra.ibge.gov.br/values/t/5938/n3/all/v/37/p/last%205",
    Fonte     = Json.Document(Web.Contents(Url, [Headers = [Accept = "application/json"]])),
    SemCabec  = List.Skip(Fonte, 1),
    Tabela    = Table.FromRecords(SemCabec),
    Colunas   = Table.SelectColumns(Tabela, {"D1C", "D3N", "V"}),
    Renomeado = Table.RenameColumns(Colunas,
                    {{"D1C", "id_uf"}, {"D3N", "ano"}, {"V", "pib_mil_reais"}}),
    Tipos     = Table.TransformColumnTypes(Renomeado,
                    {{"id_uf", Int64.Type}, {"ano", Int64.Type}, {"pib_mil_reais", type number}}, "en-US"),
    // converte "mil reais" para reais: evita confusão de unidade no relatório
    EmReais   = Table.AddColumn(Tipos, "pib_reais", each [pib_mil_reais] * 1000, type number),
    Final     = Table.RemoveColumns(EmReais, {"pib_mil_reais"})
in
    Final

Resultado esperado: 135 linhas, anos de 2019 a 2023. Clique em Fechar e Aplicar.

i

Por que o código "en-US" na conversão? A API manda os números como texto sem separador ("1796460"). Informar a cultura garante que o Power BI converta igual em qualquer computador, configurado em português ou inglês.

03Relacionamentos: o modelo estrela

Temos duas tabelas de fatos (população e PIB) que não conversam entre si. Os relacionamentos fazem as duas obedecerem aos mesmos filtros de estado e de ano.

População tem 2020, 2021, 2024, 2025, 2026. PIB tem 2019 a 2023. Precisamos de uma tabela de anos que contenha todos. Vá em Modelagem → Nova tabela e escreva:

DAX · tabela calculada
dAno =
VAR AnoIni = MIN ( MIN ( fPopulacao[ano] ), MIN ( fPIB[ano] ) )
VAR AnoFim = MAX ( MAX ( fPopulacao[ano] ), MAX ( fPIB[ano] ) )
RETURN
    SELECTCOLUMNS ( GENERATESERIES ( AnoIni, AnoFim, 1 ), "Ano", [Value] )

Resultado: uma coluna Ano de 2019 a 2026 (8 linhas). Note que a tabela é dinâmica: quando a API trouxer 2027, ela cresce sozinha.

Clique no ícone Exibição de modelo (terceiro ícone da barra esquerda). Organize as dimensões em cima e os fatos embaixo. Depois arraste a coluna da dimensão até a coluna equivalente do fato:

De (lado 1)Para (lado *)CardinalidadeDireção do filtro
dEstado[id_uf]fPopulacao[id_uf]Um para muitos (1:*)Única
dEstado[id_uf]fPIB[id_uf]Um para muitos (1:*)Única
dAno[Ano]fPopulacao[ano]Um para muitos (1:*)Única
dAno[Ano]fPIB[ano]Um para muitos (1:*)Única

Confira em Página Inicial → Gerenciar relações: devem aparecer exatamente estas 4 linhas, todas ativas.

?
Por que não ligar fPIB direto com fPopulacao

Nas duas tabelas o id_uf se repete (35 aparece 5 vezes em cada). Ligar fato com fato gera relação muitos para muitos, que dá totais errados e é difícil de explicar. A regra do modelo estrela: fato só se liga a dimensão, e a dimensão tem um valor único de cada chave.

i

Teste do relacionamento: crie uma tabela visual com dEstado[uf] e fPopulacao[populacao]. Se aparecer o mesmo número repetido em todas as linhas, a ligação está faltando ou errada.

  • Nos fatos, clique com o botão direito em id_uf e ano → Ocultar na exibição de relatório. Quem monta o gráfico deve usar dEstado[uf] e dAno[Ano].
  • Em dAno[Ano], mude Resumir por para Não resumir (senão o Power BI soma os anos: 2019 + 2020 + …).
  • Em dEstado[uf], defina Categoria de dados = Estado ou Província, para mapas funcionarem.

04Medidas DAX: transformando dados em respostas

Uma medida é uma fórmula que o Power BI recalcula para cada filtro do relatório: por estado, por região, por ano. Você escreve uma vez e ela funciona em qualquer visual.

i
Antes de começar

Crie uma tabela só para guardar medidas: Página Inicial → Inserir dados, nome _Medidas, Carregar. Depois, com ela selecionada, use Nova medida para cada fórmula abaixo. O “_” coloca a tabela no topo da lista.

Coluna calculada ou medida?

Coluna calculadaMedida
Quando calculaUma vez, ao atualizar os dadosNa hora, a cada clique e filtro
Calcula sobreUma linha por vezO conjunto filtrado
Ocupa memóriaSim, vira coluna na tabelaNão
Exemplo aquipib_bilhoes = fPIB[pib_reais] / 1e9PIB per capita

Regra prática: se o resultado é uma razão, percentual ou ranking, ele precisa ser medida. Somar PIB per capita de 27 estados não dá o PIB per capita do Brasil.

DAX · medidas
População = SUM ( fPopulacao[populacao] )

PIB (R$) = SUM ( fPIB[pib_reais] )

Formate: População como número inteiro com separador de milhar; PIB (R$) como moeda com unidade de exibição Trilhões ou Bilhões.

?
Por que criar medida para uma simples soma

Arrastar a coluna também soma, mas as medidas seguintes reaproveitam [PIB (R$)]. Se um dia a regra mudar (por exemplo, PIB a preços constantes), você troca em um lugar só. Isso se chama medida base.

✓
Confira

Em um cartão filtrado por 2021: População = 213.317.639 e PIB = R$ 9,01 tri. Em 2023: PIB = R$ 10,94 tri.

DAX
PIB per capita = DIVIDE ( [PIB (R$)], [População] )

Análise: PIB per capita é quanto de riqueza o estado produz por habitante. São Paulo tem o maior PIB, mas o Distrito Federal tem o maior PIB per capita (R$ 92.732 em 2021) por concentrar a administração federal com população menor. O Maranhão fica em último (R$ 17.472): uma diferença de mais de 5 vezes dentro do mesmo país.

?
Por que DIVIDE e não a barra /

DIVIDE devolve vazio quando o divisor é zero ou vazio, em vez de erro. E aqui isso acontece: em 2022 e 2023 existe PIB mas não existe população estimada. Com DIVIDE, esses anos simplesmente ficam em branco no gráfico.

✓
Confira

Brasil 2021 = R$ 42.248. Os únicos anos com valor são 2020 e 2021, os dois que existem nas duas fontes.

DAX
% PIB Brasil =
DIVIDE (
    [PIB (R$)],
    CALCULATE ( [PIB (R$)], ALL ( dEstado ) )   -- PIB de todos os estados
)

Como ler: CALCULATE recalcula uma medida mudando os filtros. ALL(dEstado) manda ignorar qualquer filtro de estado ou região. Então, na linha de São Paulo, o numerador é o PIB de SP e o denominador é o PIB do Brasil. O filtro de ano continua valendo, porque só removemos o de estado.

Análise: em 2023, São Paulo sozinho tem 31,5% do PIB nacional e o Sudeste tem 53,0%. Mais da metade da economia está em 4 dos 27 estados. É esse tipo de número que embasa debates sobre desigualdade regional.

i

Formate como Porcentagem com 1 casa decimal. Na tabela visual, a linha de Total deve dar 100%.

DAX
Ranking PIB per capita =
IF (
    HASONEVALUE ( dEstado[uf] ),
    RANKX ( ALL ( dEstado[uf] ), [PIB per capita], , DESC, Dense )
)

RANKX percorre a lista de todos os estados (ALL), calcula o PIB per capita de cada um e devolve a posição do estado atual. O IF(HASONEVALUE…) evita mostrar um ranking sem sentido na linha de Total.

✓
Confira (2021)

1º DF, 2º MT, 3º SC, 4º SP, 5º RJ. Último (27º): MA.

DAX
PIB Ano Anterior =
VAR AnoAtual = MAX ( dAno[Ano] )
RETURN
    CALCULATE ( [PIB (R$)], dAno[Ano] = AnoAtual - 1 )

Var. % PIB =
DIVIDE ( [PIB (R$)] - [PIB Ano Anterior], [PIB Ano Anterior] )

Por que a variável VAR: ela guarda o ano que está no filtro antes do CALCULATE trocar o filtro. Sem ela, você estaria comparando o ano com ele mesmo.

Análise: de 2022 para 2023 o PIB nominal do Brasil cresceu 8,6%. Roraima (+19,1%), Amapá (+18,7%) e Alagoas (+17,9%) cresceram mais; o Rio de Janeiro, só 1,7%. Lembre: é PIB a preços correntes, ou seja, inclui a inflação do período.

!

Usamos dAno (e não uma tabela de datas) porque o IBGE publica dados anuais. Funções como SAMEPERIODLASTYEAR exigem uma tabela calendário com datas diárias; isso fica para a próxima aula.

06Erros comuns e como resolver

Todos os estados mostram o mesmo valor

Falta relacionamento entre a dimensão usada no eixo e o fato da medida, ou ele está inativo (linha tracejada). Volte ao Passo 3.2 e confira Gerenciar relações.

“Não é possível criar uma relação entre duas colunas porque uma das colunas deve ter valores exclusivos”

Você arrastou do fato para o fato, ou a dimensão tem chave repetida. A relação deve partir de dEstado[id_uf] ou dAno[Ano].

PIB aparece mil vezes menor do que deveria

Faltou a etapa EmReais do Passo 2.7. O SIDRA entrega em mil reais.

Erro “Expression.Error: A coluna 'D1C' da tabela não foi encontrada”

A API devolveu XML ou uma mensagem de erro em vez do JSON. Confira se a URL está igual (incluindo %20) e se o cabeçalho Accept = "application/json" está no código.

PIB per capita em branco

Correto para 2019, 2022 e 2023: nesses anos falta população ou PIB. É uma limitação da fonte e precisa estar explicada no painel (uma caixa de texto resolve).

O slicer de ano mostra “Soma de Ano”

Em dAno[Ano], defina Resumir por: Não resumir.

07Atividades: agora é com você

Faça na ordem: cada atividade usa uma ideia nova. As dicas ficam fechadas; tente primeiro sem abrir.

A1 · Participação na população

Básico

Crie a medida % População Brasil no mesmo modelo de % PIB Brasil. Coloque as duas lado a lado numa tabela por estado.

Analise: quais estados têm % do PIB maior que % da população? O que isso diz sobre eles?

Dica

Troque [PIB (R$)] por [População] nas duas partes do DIVIDE.

A2 · Top 5 e filtros de visual

Básico

Duplique o gráfico de PIB per capita e deixe só os 5 maiores estados, sem escrever DAX.

Dica

Painel Filtros → filtro do visual em sigla_uf → Tipo de filtro N superior → Mostrar itens: Superior 5, Por valor: [PIB per capita].

A3 · Crescimento populacional recente

Intermediário

Crie Cresc. Pop. 2024-2026 mostrando a variação % da população entre 2024 e 2026, por estado, que funcione mesmo sem filtro de ano.

Analise: quais estados mais cresceram e quais perderam população? Pesquise uma explicação para um deles.

Dica
VAR P24 = CALCULATE ( [População], dAno[Ano] = 2024 )
VAR P26 = CALCULATE ( [População], dAno[Ano] = 2026 )
RETURN DIVIDE ( P26 - P24, P24 )

Por que começar em 2024 e não em 2021? As estimativas antes do Censo 2022 usavam outra base e não são comparáveis com as de depois.

A4 · Faixas de riqueza (coluna calculada)

Intermediário

Na tabela dEstado, crie a coluna Faixa PIB per capita 2021 com os valores “Alta” (acima de R$ 50 mil), “Média” (R$ 30 a 50 mil) e “Baixa”. Use-a como legenda de um gráfico.

Dica
Faixa PIB per capita 2021 =
VAR PC = CALCULATE ( [PIB per capita], dAno[Ano] = 2021 )
RETURN SWITCH ( TRUE (), PC > 50000, "Alta", PC >= 30000, "Média", "Baixa" )

O CALCULATE dentro de uma coluna calculada faz a transição de contexto: a linha do estado vira filtro. Sem ele, todos os estados receberiam o valor do Brasil.

A5 · Nova fonte: área e densidade (Censo 2022)

Desafio

No SIDRA, encontre a tabela do Censo 2022 com área territorial das UFs (pesquise “densidade demográfica” na busca do SIDRA). Gere a URL em Links de Compartilhar, importe como fArea, relacione com dEstado e crie a medida Densidade (hab/km²).

Analise: faça um gráfico de dispersão com PIB per capita × densidade. Existe relação?

Dica

Reaproveite o código M de fPopulacao: só mudam a URL e os nomes das colunas. Confira a unidade (km²) antes de dividir.

A6 · Dashboard final

Entrega

Monte um relatório de 2 páginas:
